# Soliq release checklist

- Confirm all four authors, contributions, actual affiliations and contact details.
- Keep NASA/product citations and the distinction between observations and models.
- Document input versions, QC, exact periods, source hashes and model assumptions.
- Run tests and benchmarks on GitHub for the release commit; retain run URLs/artifacts.
- Review labels, units, keyboard access and mobile layout against that exact version.
- Review every quantitative pitch claim against an executed result and evidence class.
- Include independent-validation results only after they exist and can be reproduced.
- Retain the development repository. Use an additive tagged release; no history rewriting.
- Keep secrets, private farmer records and platform-only hosting metadata out of the public snapshot.
- Select a code license with the team; do not invent institutional endorsement.
- Do not create the final judges' repository until the team identifies it and the release is ready.
